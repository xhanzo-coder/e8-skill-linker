# 链接、同步、迁移与停用

## 链接 skill

先从运行环境取得实际工作目录。用户说“当前项目”时，在已核实的工作目录下传 `--project .`；指定其他项目时验证其目录存在并在计划中显示完整路径。禁止手抄后替换引号、忽略 `cd` 失败或创建缺失项目根目录。`link`、`link-many`、`init` 与安装流程仅在已有项目中创建入口。

项目 skill 入口统一指向中央库根层入口，再由中央入口指向 `.repos` 内包含 `SKILL.md` 的具体目录。不要将项目直接链接到 `.repos`、host 或整个 skill pack。脚本收到已登记的仓库内 skill 路径时，会选用对应中央入口。

链接是否相同按“直接目标”判断，不只比较最终解析路径。旧项目若直接指向 `.repos`，不会被当作已符合新结构；列出旧目标和中央入口，按确认计划先 unlink 再 link。保留中央原件。Windows junction 与 symlink 使用同样规则。

链接 skill 时，要求源目录有效且包含 `SKILL.md`。如果目标名称已经存在：

- 如果它已经是同一个软链接，报告无需修改。
- 如果它是失效链接或指向其他目标的链接，停止并询问是否先取消链接再重建；不要直接覆盖。
- 如果它是真实目录或文件，不要覆盖；建议备份、手动迁移或跳过。

软链接目标必须受控：

- 单个 skill 链接的源目录必须位于当前生效配置的中央 skills 库内，或当前项目 `.agents/skills` 内。
- `.codex/skills` 和 `.claude/skills` 只能链接到当前项目 `.agents/skills`。
- 迁移后在原位置创建的链接只能指向当前生效配置的中央 skills 库。
- 不要把任意下载目录、临时目录、桌面目录、仓库根目录、用户全局 skills 目录或其他未授权路径直接作为软链接目标。
- 如果用户提供的源路径不在允许范围内，先建议把该 skill 迁移或复制到中央库，再从中央库链接到项目。

## 批量链接

批量链接多个 skills 时，先逐个验证源目录都包含 `SKILL.md`，并检查名称重复、路径越界和所有目标冲突，再列出计划创建的全部链接。任何预检失败时都不要开始写入；只在用户确认后执行 `link-many --execute`。

## 删除或停用 skill

删除或停用 skill 时，默认只从当前项目停用，不删除中央原件。先检查目标路径属于用户级还是项目级，以及它是软链接、junction、真实目录、失效链接还是不存在。

- 如果目标是项目级软链接或 junction，只删除链接本身。
- 如果目标是真实目录，停止并说明删除会删除 skill 内容本身，建议迁移、备份或只取消引用。
- 如果用户明确要求删除中央原件，必须列出影响范围，说明所有指向它的项目可能变成失效链接，并要求明确确认口令，例如 `确认删除中央原件 write-blog`。

## 迁移已有真实目录

迁移按[首次使用与接管](first-use-and-adoption.md)执行。先盘点，由用户选项，不因 `default_mode=centralize` 自动接管全部真实目录。`migrate` 现在是有备份的本地快照接管：复制核验、保留原件备份、在原位置建链接、写入本地接管记录。保留原用户级/项目级可见范围，不自动改成项目专用。

目标中央路径已存在时停止；中央库必须等于活动库且不在 Agent 发现目录内。执行须带已确认计划的内容摘要和依赖审查参数，内容变化后重新计划。内部链接、Git 元数据、系统/插件目录不使用普通快照迁移。恢复通过 `restore-adoption` 的凭据预览及确认执行，保留中央副本，不覆盖修改过的内容。

## 同步多个 Agent

同步多个 Agent 时，优先使用当前项目 `.agents/skills` 作为项目级入口目录，并且只在用户确认后把 `.claude/skills` 和 `.codex/skills` 链接到它。不要把这个项目级入口目录称为中央 skills 库。

如果其中任一目录已经是真实目录，报告冲突并让用户选择处理方式。不要用软链接覆盖已有的真实目录。

安装/链接执行后检查准确的项目入口路径、直接目标及其 `SKILL.md`；报告脚本输出的 `verified_project_entries`，不要仅凭中央入口存在就断言项目安装成功。

初始化多个 Agent 入口时，先预检所有入口。任一入口冲突时都不要创建其他入口或项目 hub，避免留下半完成状态。

## 共享项目注意事项

对共享或团队项目，要提醒用户：`/Users/name/...` 这类绝对软链接在别人电脑上可能变成失效链接。对团队仓库，尽量使用相对软链接；如果不合适，就提供安装脚本或说明，避免提交绝对软链接。
